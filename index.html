01foundations

Artificial Intelligence

Broad field for building intelligent systems that perform tasks normally needing human intelligence:

  • perception
  • reasoning
  • learning
  • problem solving
  • decision-making

It's an umbrella term — ML, Deep Learning and Gen-AI all sit underneath it.

04foundations

AI is not always ML

tap to flip ✦

04foundations

Example: MYCIN expert system

Built in the 1970s to diagnose patients from symptoms and test results.

  • 500+ explicit rules
  • simple yes/no or textual questions
  • output: ranked culprit bacteria + reasoning + dosage
  • never deployed — PCs didn't exist yet

Why this matters: MYCIN was AI but not ML. Rules were hand-coded, not learned from data.

05foundations

Neural Networks

tap to flip ✦

05foundations

How they work

  • nodes (tiny units) connected together, organised in layers
  • "deep" learning = more than one hidden layer
  • sees data, finds patterns, changes connections between nodes
  • nodes "talk" to each other — pass data (or not) to the next layer
  • can have billions of nodes

Each layer learns a pattern: e.g. vertical lines for 1/4/7, curved bottoms for 6/8/0.

Needs large data + GPUs for parallel compute.

06modern AI

Gen-AI in a nutshell

  • subset of Deep Learning
  • multi-purpose foundation models backed by neural networks
  • can be fine-tuned to better fit specific use cases
  • generates new content from prompts: text, images, audio, video, code

Key idea: one big pre-trained model adapted to many tasks rather than training from scratch each time.

07modern AI

Transformers & LLMs

07modern AI

Why they're powerful

  • process a sentence as a whole (not word-by-word)
  • faster, more efficient training
  • give relative importance to words → coherent output
  • trained on vast internet + book text

Examples:

  • BERT — Google, bidirectional reading
  • ChatGPT / GPT — OpenAI (Chat Generative Pretrained Transformer)

Softmax tip: used in the last layer for multi-class classification.

08modern AI

Diffusion Models

tap to flip ✦

08modern AI

e.g. Stable Diffusion

Models that learn to reverse a noising process.

  • training: add noise to images step-by-step until pure noise
  • then learn to undo each step
  • at generation time: start from random noise and progressively denoise into an image

Use case: high-quality image generation from text prompts (Stable Diffusion, DALL·E, Midjourney-style models).

09modern AI

Multi-modal Models

09modern AI

e.g. GPT-4o

Models that handle multiple input and output types.

  • do not rely on a single input type
  • do not produce a single output type

Example: takes a mix of audio + image + text → outputs video + text.

Useful for tasks like: image captioning, visual Q&A, voice + image assistants.

Labeled vs Unlabeled

tap to flip ✦

11training data

Two flavours of data

Labeled — input features + matching output labels

  • e.g. images tagged "cat" or "dog"
  • used for Supervised Learning
  • powerful but expensive to produce at scale

Unlabeled — input features only, no labels

  • e.g. a collection of unlabelled images
  • used for Unsupervised Learning — find patterns / structures

Garbage in → garbage out ✦ training data is the most critical stage.

12training data

Structured vs Unstructured

tap to flip ✦

12training data

Format matters

Structured — rows & columns (Excel-style)

  • Tabular — customer DB: name, age, total purchase
  • Time series — stock prices recorded daily

Unstructured — text-heavy or multimedia

  • Text — articles, social posts, reviews
  • Image — object recognition data

Different formats → different algorithms can be applied.

Regression

14supervised

Predict a number

Predict a numeric, continuous value based on input data — output can take any value in a range.

Use cases:

  • house prices (size, location, bedrooms)
  • stock price prediction
  • weather forecasting

Quick test: if the answer is a number on a scale, it's regression.

15supervised

Classification

tap to flip ✦

15supervised

Predict a category

Predict a categorical label — output falls in a specific class.

Types:

  • Binary — spam / not spam
  • Multiclass — mammal / bird / reptile
  • Multi-label — movie tagged "action" AND "comedy"

Use cases: fraud, image classification, customer retention, diagnostics.

Key algorithm: k-Nearest Neighbours (k-NN).

16feature eng.

Feature Engineering

tap to flip ✦

16feature eng.

Make data meaningful

Use domain knowledge to transform raw data into meaningful features. Especially important for supervised learning.

Techniques:

  • Extraction — derive features (age from DOB)
  • Selection — pick the relevant features
  • Transformation — normalise so algorithms converge faster

Structured: create "price per sqft", normalise scales.

Unstructured: TF-IDF / embeddings for text; edges/textures via CNNs for images.

Unsupervised: Clustering

17other

Find natural groups

Groups similar data points into clusters based on features. No labels needed — the machine finds the groups; humans name them.

Example: customer segmentation

  • Data: purchase history (frequency, avg value)
  • Technique: K-means
  • Outcome: target each segment with tailored marketing

Other use cases: targeted marketing, recommender systems, anomaly detection.

18other

18other

Market basket analysis

Discovers which products are frequently bought together.

Example: supermarket

  • Data: transaction records
  • Goal: optimise product placement + promos
  • Technique: Apriori algorithm

Outcome: place pasta near sauce → boost sales.

Also unsupervised — finds patterns in unlabeled transaction data.

19other

Semi-Supervised

tap to flip ✦

19other

Best of both worlds

Small amount of labeled data + large amount of unlabeled data.

Process:

  • train initial model on labeled data
  • algorithm labels the unlabeled data itself — called pseudo-labeling
  • retrain model on the resulting data mix

Why bother? Labeling is expensive. This lets you leverage cheap unlabeled data.

20other

Self-Supervised

tap to flip ✦

20other

No humans needed first

Model generates pseudo-labels for its own data — humans don't label anything upfront.

Used to pre-train on huge unlabeled datasets, then fine-tune for downstream tasks.

Pre-text tasks teach a representation:

  • predict the future from the past
  • predict the masked from the visible
  • predict any occluded part from visible parts

Used widely in NLP (BERT, GPT) and image recognition.

22other

RLHF

tap to flip ✦

22other

RL from Human Feedback

Uses human preferences in the reward function → aligns models with human goals.

Four steps (e.g. company chatbot):

  1. Data collection — human prompts + responses
  2. Supervised fine-tuning — fine-tune base model; compare to human answers
  3. Build reward model — humans pick preferred responses; reward model learns preferences
  4. Optimise with RL — use reward model as RL reward (can be automated)

Used throughout modern LLMs ✦

24evaluation

Bias vs Variance

tap to flip ✦

24evaluation

The trade-off

Bias — error between predicted & actual.

  • High bias = doesn't match training data → underfitting
  • Reduce: more complex model, more features

Variance — how much performance shifts on a different but similar dataset.

  • High variance = sensitive to data → overfitting
  • Reduce: feature selection, multiple train/test splits

Memorable image: bias = consistently missing the target; variance = scattered shots.

Classification metrics

Precision = TP / (TP + FP)

Recall = TP / (TP + FN)

Accuracy = (TP+TN) / total

MetricBest when…
PrecisionFPs are costly
RecallFNs are costly
F1imbalanced datasets
Accuracybalanced sets (rare)

Spam example: recall = catching all spam; precision = not flagging real emails.

26evaluation

AUC-ROC

tap to flip ✦

26evaluation

Area Under ROC Curve

Plots True Positive Rate vs False Positive Rate at various classification thresholds.

  • AUC range: 0 to 1
  • 1 = perfect model
  • 0.5 = random guessing (the diagonal)
  • uses sensitivity (TPR) and 1 − specificity (FPR)

Compare curves across models → find the threshold that suits your business case.

Real-time vs Batch

29production

Inferencing modes

Real-time

  • quick decisions as data arrives
  • speed > perfect accuracy
  • e.g. chatbots, fraud check at checkout

Batch

  • large amount analysed all at once
  • accuracy > speed
  • e.g. nightly analytics jobs, monthly reports

Edge: Small Language Model on device → low latency, offline. LLM on remote server → more powerful but online only.

31production

When NOT to use ML

tap to flip ✦

31production

Deterministic problems

If the problem is well-framed and the solution can be computed, just write code.

Example:

  • Deck of 5 red + 3 blue + 2 yellow cards
  • P(drawing blue) = 3/10 — exact

Don't use ML when:

  • exact answer is computable
  • rules are known and stable
  • cost / interpretability matter more than approximation

LLMs with reasoning still aren't perfect for deterministic maths.
